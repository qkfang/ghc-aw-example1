# ghc-aw-example1

Proof of concept: **an asynchronous agent that monitors codebases for AI solutions that
haven't been logged in the AI Governance Register**, built with
[GitHub Agentic Workflows (gh-aw)](https://github.github.com/gh-aw/) and a Copilot custom agent.

## What's in the repo

| Path | Purpose |
|------|---------|
| `governance/ai-register.yml` | The AI Governance Register – the source of truth for approved AI solutions. |
| `governance/detection-rules.md` | What the agent treats as "AI usage" (SDKs, endpoints, IaC, packages). |
| `.github/workflows/ai-governance-scan.md` | The agentic workflow (natural-language instructions + frontmatter). |
| `.github/workflows/ai-governance-scan.lock.yml` | Compiled GitHub Actions workflow generated by `gh aw compile` – do not edit by hand. |
| `governance/copilot-agent/ai-governance-scanner.agent.md` | Copilot custom agent for on-demand / interactive scans. |
| `samples/registered-summarizer/` | Test fixture: AI app that **is** in the register (should not be flagged). |
| `samples/unregistered-chatbot/` | Test fixture: AI app that is **not** in the register (should be flagged). |

## How it works

```
schedule (weekly) / manual dispatch / push to governance or samples
        │
        ▼
Copilot agent in GitHub Actions (read-only token, sandboxed network)
  1. reads governance/ai-register.yml + detection-rules.md
  2. finds AI usage  – scope=repo: grep the checkout
                     – scope=org : repo search owner:<owner>, then code search
                                   repo:<owner>/<name> – first `max_repos` (default 5),
                                   remote only, never cloned
  3. matches each finding to register entries (repository + path prefix)
        │
        ▼
safe-output: create-issue  "[AI Governance] Unregistered AI solutions detected (N found)"
  – evidence links, suggested owners, ready-to-paste register YAML
(or `noop` when everything is registered)
```

The agent never gets write access: it only proposes an issue, which gh-aw's
`safe-outputs` job validates and creates.

## Try it

1. Add a Copilot token secret: `gh secret set COPILOT_GITHUB_TOKEN` (or see the
   [engine docs](https://github.github.com/gh-aw/reference/engines/)).
2. Run it on this repo: **Actions → AI Governance Scan → Run workflow → scope `repo`**
   (or `gh aw run ai-governance-scan`).
3. Expected result: an issue flagging `samples/unregistered-chatbot/` (Anthropic SDK),
   while `samples/registered-summarizer/` is treated as compliant (entry `AI-0001`).
4. Register the chatbot in `governance/ai-register.yml`, push, and the next run should
   report nothing (`noop`).

### Scanning the whole organisation

The default `GITHUB_TOKEN` can only read this repository. For `scope = org`:

1. Create a fine-grained PAT (or GitHub App) with read access to **Contents** and
   **Metadata** on all repositories you want scanned.
2. Save it as the `GH_AW_GITHUB_MCP_SERVER_TOKEN` secret – gh-aw uses it automatically
   for the GitHub MCP tools.
3. Run the workflow with `scope = org`. The schedule can also be switched to org scope
   by changing the default input.

The org scan is **remote only** – it never clones the other repositories. It lists the
owner's repositories via repository search, skips archived repositories and forks, keeps
the most recently updated `max_repos` (default **5**, selectable per run: 3 / 5 / 10 / 20),
and probes each one with `search_code` before fetching only the manifests that matched.
Four constraints of the search APIs are baked into the instructions:

- List repositories with `owner:<owner>` – it matches both user and organisation
  accounts, while `org:<owner>` returns zero results for a personal account (and
  `user:` for an org).
- Scope each code search with `repo:<owner>/<name>` – code search does not support the
  `owner:` qualifier.
- Quote every signal (a quoted phrase matches dots and spaces fine) and never join
  signals with `OR` – `Azure.AI.OpenAI OR Microsoft.SemanticKernel` returns nothing.
- Code search allows ~10 requests/minute, so each repository is probed with the
  "First-pass probe signals" short list in `detection-rules.md` rather than the full
  detection table, and the issue reports reduced coverage if rate limiting cuts a run
  short.

Tip: host this in a central "governance" repository so the register and the monitor
live together, and use `safe-outputs.create-issue.target-repo` if you want issues filed
in a different tracking repo.

### Using the custom agent (interactive / on-demand)

Copy `governance/copilot-agent/ai-governance-scanner.agent.md` into `.github/agents/`
(repo-level) or your organisation's `.github-private` repository (org-wide). Then pick
**ai-governance-scanner** in Copilot Chat / Copilot cloud agent and ask e.g.
*"Scan org:my-org for unregistered AI solutions and open a PR adding draft register entries."*

## Editing the workflow

After changing `.github/workflows/ai-governance-scan.md`, recompile:

```bash
gh extension install github/gh-aw   # once
gh aw compile ai-governance-scan
```
